# Автомат с едой (задача №4): описание программы

Файлы: `sw/vending.asm` (программа), `tb/tb_vending.v` (тестбенч), `sw/vending.rom.mem` и `sw/vending.lst` (результат ассемблера).

## Поведение

| Параметр | Значение |
|---|---|
| Товар | один, цена `PRICE` = 7 руб. (константа `.equ`, допустимо 1…255) |
| Монеты | клавиши `1`, `2`, `5` добавляют 1, 2, 5 руб. к балансу |
| Отмена | клавиша `15` возвращает внесённую сумму |
| Остальные клавиши | в режиме приёма монет игнорируются |
| Индикаторы (`SEG`) | баланс; после покупки или отмены — сдача (возврат). Ведущие нули погашены, `0` показывается как «0» |
| `LED0` (бит 0) | товар выдан |
| `LED1` (бит 1) | показана сдача (возврат) |

Светодиоды служат признаком режима: оба погашены — на индикаторах баланс; горит `LED1` — сдача или возврат.

### Правила
1. Как только баланс ≥ цены, товар выдаётся автоматически: `LED0` горит, на индикаторах сдача (баланс − цена); если сдача больше нуля, горит и `LED1`.
2. После покупки или возврата (режим «завершено») любое следующее нажатие **только сбрасывает автомат** (баланс 0, светодиоды погашены, индикатор «0») и больше ничего не делает: нажатая клавиша не засчитывается.
3. Отмена при нулевом балансе ничего не делает.
4. При цене 7 баланс перед покупкой не превышает 6 + 5 = 11. При изменении `PRICE` это стоит перепроверить.

## Регистры

| Регистр | Назначение |
|---|---|
| R1 | баланс |
| R2 | код клавиши / временный |
| R3, R4 | временные (`show` использует R2, R3, R4) |
| R5 | состояние: 0 — приём монет, 1 — операция завершена |
| R6 | база MMIO (`0xFF00`) |
| R7 | регистр связи (`CALL`/`RET`) |

## Структура программы

```
start:  R6 = MMIO
reset:  баланс = 0, состояние = 0, LED = 0, показать 0
wait:   опрос KEY_STATUS (SHR -> C = VALID); при нажатии читаем KEY_DATA
        состояние == 1 ?  -> reset
        клавиша 1/2/5     -> баланс += монета; показать баланс; если баланс >= цены -> покупка
        клавиша 15        -> если баланс > 0: возврат
        иначе             -> игнорировать
show:   подпрограмма: BIN2BCD + гашение ведущих нулей + запись в SEG
```

## Тестовые сценарии (`make vending`, 36 проверок)

Тестбенч имитирует клавиатуру; перед каждым нажатием ждёт `VALID = 0`, после нажатия даёт программе 400 тактов на обработку и сравнивает `SEG` и `LED`.

| № | Последовательность | Ожидаемый результат |
|---|---|---|
| 1 | `5, 2` | товар без сдачи: `LED = 01`, индикатор «0» |
| 2 | `5, 5` | товар и сдача 3: `LED = 11`, индикатор «3» |
| 3 | `2, 1, 15` | возврат 3: `LED = 10`, индикатор «3», товара нет |
| 4 | `1` × 7 | накопление 1…7, на седьмой монете товар без сдачи |
| 5 | `2, 2, 2, 2` | товар и сдача 1 |
| 6 | `5, 5, 5, 1` | после покупки `5` только сбрасывает (баланс 0, а не 5), затем `1` принимается |
| 7 | `2, 15, 1` | после возврата `1` только сбрасывает |
| 8 | `15, 9, 0` при балансе 0 | ничего не меняется |
| 9 | `5, 3, 14, 2` | клавиши 3 и 14 игнорируются, затем товар |
| 10 | `5, 1, 5` | максимальная сдача 4 |

Дополнительная проверка (вне репозитория): 40 случайных последовательностей нажатий сравнены с эталонной моделью на Python — расхождений нет.

Интерактивная проверка в реальном времени (требование задания «взаимодействует с пользователем в реальном времени») выполняется на этапе 5 через мост с клавиатурой ПК.
